# 분할 리뷰 결과 취합 보존

분할 리뷰와 전역 리뷰가 완료된 뒤 같은 finding을 LLM에 재작성시키면 출력 길이 제한 또는 필드 변경으로 최종 정합성 검사가 실패한다. 입력 리뷰 내용 자체는 이미 검증됐으며 최종 변환에서 새 판단을 할 필요가 없다.

- 모든 내부 리뷰가 완료되면 시스템은 검증·중복 제거된 finding을 최종 게시 모델로 결정적으로 변환해야 한다.
- 변환 시 시스템은 category, file, line, description, suggestion, confidence, spec_status, aligned, prior_resolved를 기존 계약대로 보존해야 한다.
- 변환이 끝나면 시스템은 기존 finding 집합 정합성 검사를 수행해야 한다.
- 내부 리뷰 응답이 불완전하거나 범위를 벗어나면 시스템은 실패를 유지해야 한다.
- 시스템은 단일 리뷰 경로, 파일 범위 검사, 판정 기준과 비용 상한을 유지해야 한다.

## 실제 분할 리뷰 범위 오류 보수

PR #238의 필수 리뷰는 내부 `analysis shard-2` 응답이 배정 파일 밖 finding을 반환하여 두 번 모두 `RESPONSE_SCHEMA_ERROR`로 종료됐다. 기존 사후 검증은 올바르게 실패했지만, 모델 요청의 Structured Outputs 스키마는 담당 파일 범위를 제한하지 않았다. 리뷰 결과가 게시되기 전에 멈춘 정상 입력 경로다.

- 내부 리뷰 unit 요청 시, 시스템은 해당 unit에 배정된 파일만 `finding.file`의 문자열 값으로 허용하고 기존 `null` 값을 허용해야 한다.
- 내부 리뷰 unit 요청 시, 시스템은 `covered_paths` 항목을 해당 unit의 배정 파일로 제한하고 `unit_id`를 해당 unit ID로 제한해야 한다.
- 전역 리뷰 unit 요청 시, 시스템은 전체 변경 파일과 전역 unit ID를 같은 방식으로 제한해야 한다.
- 단일 리뷰 요청 시, 시스템은 기존 `ReviewResult` 응답 스키마를 유지해야 한다.
- 범위 밖·중복·누락·잘못된 unit 또는 category의 응답이 도착하면, 시스템은 기존 사후 검증에서 실패해야 한다.
- 모델 요청 비용을 예약하기 전에, 시스템은 각 unit에 실제 전달할 범위 제한 스키마의 토큰을 포함해 상한을 계산해야 한다.
- 여러 unit이 동시에 실행되는 동안, 시스템은 각 unit의 스키마와 공용 정적 스키마를 서로 변경하지 않아야 한다.
